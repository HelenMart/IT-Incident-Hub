\# Estrategia de ramas — IT Incident Hub



La rama principal del proyecto es `main`, donde se integran los cambios revisados.



Para desarrollar funcionalidades y mejoras se utilizan ramas independientes.



\## Convenciones



\- `feature/\*`: implementación de nuevas funcionalidades.

\- `fix/\*`: corrección de errores y problemas técnicos.

\- `docs/\*`: documentación del proyecto.



\## Proceso de integración



1\. Crear una rama desde `main`.

2\. Realizar los cambios necesarios.

3\. Registrar los cambios mediante commits descriptivos.

4\. Subir la rama a GitHub.

5\. Crear un Pull Request.

6\. Ejecutar las comprobaciones automáticas.

7\. Revisar los resultados y fusionar los cambios aprobados.



Los cambios relevantes deben vincularse con los elementos de trabajo de Azure Boards cuando corresponda.
